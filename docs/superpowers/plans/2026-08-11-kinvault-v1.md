# KinVault v1 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build a polished local-first KinVault web app with synthetic demo documents, SQLite metadata, deterministic cited Q&A, upload/review flows, and privacy controls.

**Architecture:** A Next.js App Router application serves a Finder-inspired client UI and typed route handlers. Domain functions stay framework-free and are tested with Vitest; a small repository wraps SQLite, while a storage service keeps originals below a local vault root. A deterministic answer service sits behind an extraction interface so an offline fixture extractor can be replaced later without changing the UI contract.

**Tech Stack:** Next.js 15, React 19, TypeScript 5, better-sqlite3, Vitest, Zod, and Lucide React. CSS is authored in `app/globals.css` with system fonts and no component-kit dependency.

## Global Constraints

- Seeded demo data is synthetic only; never add real family documents or identifiers.
- Every answer must include document title, page number, extracted field label, and confidence.
- Missing fields return `Not found in the vault`; the answer service never guesses.
- Payment-card content is rejected; ordinary identity and insurance records remain supported.
- The default server binds to localhost and makes no paid API or external OCR request.
- Files are stored under a vault root; path traversal and absolute paths are rejected.
- Write tests first, run the focused test red, then implement the smallest green change and commit each meaningful feature.
